# Outlook 邮箱接入

后台0.7.0可连接个人 Outlook、Hotmail、Live 等微软邮箱。邮箱授权保存在服务器，运营登录自己的系统账号即可在任意电脑查看被分配邮箱的验证码。手机 App 无需改动。

## 一、站点只配置一套微软应用

需要有权限注册 Microsoft Entra 应用的账号或租户。20个邮箱可共用一个应用，邮箱自身不需要分别注册应用。

1. 在 [Microsoft Entra 管理中心](https://entra.microsoft.com/) 打开应用注册，新建自己的应用。
2. 支持账号类型选择包含“个人 Microsoft 账户”的选项，例如组织目录及个人 Microsoft 账户，或仅个人 Microsoft 账户。
3. 添加 **Web** 平台回调地址，例如 `https://sim.example.com/oauth/outlook/callback`。域名改为本站域名，路径保持完全一致，使用 HTTPS。
4. 添加 Microsoft Graph **委托权限** `User.Read`、`Mail.Read`，授权流程还会请求 `offline_access`。本项目不申请发送、删除或修改原邮箱邮件的权限。
5. 创建客户端密钥，记录其 **Value／值**，不是 Secret ID；同时记录应用的客户端 ID 和密钥到期时间；到期前更新密钥值，保持客户端 ID 不变时系统保留已有邮箱授权。
6. 在本站「邮箱管理 → 微软应用设置」填写客户端 ID、密钥值和本站 HTTPS 根地址，保存。密钥只在服务器加密保存，不会回显。

请使用 Web 类型的回调来支持服务端续期。单页应用 SPA 类型的刷新期限和跨域设置不同，不适合本功能。若微软页面提示没有应用注册权限，需要由具备相应租户权限的账号创建应用。

微软配置变更、租户及账号验证要求以微软当前页面为准。参考 [应用账号类型](https://learn.microsoft.com/en-us/entra/identity-platform/supported-accounts-validation)、[授权码流程](https://learn.microsoft.com/en-us/entra/identity-platform/v2-oauth2-auth-code-flow)。

## 二、添加并连接邮箱

1. 在「邮箱管理」点击添加邮箱，或批量导入：每行一个邮箱。
2. 已有 `邮箱----密码` 列表也可粘贴，导入时只保留邮箱地址；密码列不会发送或存储。邮箱密码只在微软登录页面填写。
3. 对每个邮箱点击“连接 Outlook”，在微软页面登录该邮箱并同意读取邮件。系统核对实际登录地址，避免连接到浏览器中另一账号。
4. 授权成功后返回后台，邮箱显示“已连接”。首次连接仅收取之后的新邮件验证码；同一邮箱重新授权时继续原同步进度。

密码不会保存到本系统。服务器加密保存访问和刷新凭据；刷新凭据通常默认90天并在使用中换新，并非每隔90天必须人工重登。微软仍可撤销授权或要求重新验证，届时显示“需要重新授权”。参考 [刷新凭据说明](https://learn.microsoft.com/en-us/entra/identity-platform/refresh-tokens)。

## 三、启动自动收件进程

将下面路径替换为实际部署目录，PHP路径与网站PHP版本保持一致：

```bash
cd /www/wwwroot/umax-sim/server
/www/server/php/82/bin/php bin/console.php migrate
/www/server/php/82/bin/php bin/mail-worker.php --once
```

持续运行：

```bash
/www/server/php/82/bin/php /www/wwwroot/umax-sim/server/bin/mail-worker.php --loop
```

在宝塔进程守护、systemd或已有服务管理器中，以网站运行用户托管此命令，并设置退出后自动重启。工作目录为 `server`。PHP CLI需要 `curl`、`pdo_mysql`、`mbstring`、`openssl`，能读取本站 `config/config.php`、`config/keyring.php`，并可出站连接 `login.microsoftonline.com` 与 `graph.microsoft.com` 的 HTTPS443。

不要只在临时 SSH 窗口中启动。新进程默认分批处理，每个邮箱通常约30秒检查一次；邮件量、微软限流和网络会影响实际延迟。Inbox及Junk Email都会检查，关闭运营的浏览器不影响服务器收件。代码更新后进程会退出，应由进程守护自动重启。

## 四、分配运营及收码

在「邮箱列表 → 分配运营」勾选接收人，可为一个邮箱选择多人。保存后自动赋予基本邮箱查看、验证码查看和复制权限，无需再重复设置功能权限。运营刷新页面后，在自己的电脑登录后台即可收码，不需要各自在 Outlook 再登录。

邮箱范围独立于店铺范围。拥有全部店铺不自动获得全部邮箱；超级管理员可管理所有邮箱。取消某运营的邮箱勾选后，服务端立即拒绝其读取、复制及连接该邮箱，其他邮箱范围与功能权限不变。

「账户管理 → 店铺与权限」中的 Outlook 权限还可单独控制添加、编辑、删除、连接、收取、分配运营和全站微软应用设置。

## 五、内容、同步和故障

- 常见数字及数字字母混合验证码自动提取，保留前导零和字母大小写。普通订单号、物流单号不当作验证码。
- 本站仅保留邮箱快照、发件人、主题、验证码和收到时间，不保留或渲染完整邮件HTML、附件。首先读取轻量预览，仅对需要展开的验证邮件读取正文。
- 使用邮件唯一标识回执避免重复收码；删除本站验证码不会在下次同步重新出现，也不会删除原邮箱邮件。
- 微软暂时限流时按 Retry-After 重试；中断恢复后从每个文件夹的同步进度继续，不以“最近十分钟”截断丢弃邮件。
- 未运行收取进程时，后台会明确提示；“已连接”表示授权成功，不代表进程正在运行。
- 删除邮箱会断开本站连接并清除本站已同步的该邮箱验证码，原邮箱内容不受影响。
- 验证码记录默认随现有清理任务保留7天；密钥保管文件仍须与数据库一起备份。

## 实际验收

配置真实应用并连接一个自有邮箱后，用该邮箱执行一次正常登录验证码接收，在后台核对发件人、完整验证码及时间，再用一个被授权运营账号核对可见范围。无实际应用配置及账号授权时，安装包只能完成本地/模拟接口验证，不能视为真实20个邮箱已接通。
