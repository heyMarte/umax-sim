# Outlook mailbox collection implementation plan

> **For agentic workers:** Use superpowers:executing-plans inline. Track verification per task; use one whole-branch review at the end.

**Goal:** Connect approximately20 personal Outlook/Hotmail accounts through delegated OAuth and let authorized operators read their verification codes from any computer.

**Architecture:** PHP keeps encrypted Microsoft application and mailbox credentials. A background worker polls Inbox and Junk Email. Mailbox grants are separate from shop grants, with administrators retaining full access. One mailbox workspace contains accounts and collected codes.

**Tech stack:** Existing PHP8.2, MySQL/MariaDB, cURL, AES-GCM keyring, native JavaScript and Microsoft Graph v1.0.

**Spec:** User confirmed personal Outlook/Hotmail accounts with email/password only; each account connects through Microsoft's interactive authorization. Existing Android collectors remain unchanged.

## Global constraints

- No Microsoft mailbox passwords are stored or submitted by this application.
- Use server-side authorization code flow, PKCE, user-bound single-use state and encrypted token rotation.
- Request delegated User.Read, Mail.Read and offline_access; no sending or mailbox modification.
- Restrict network destinations to Microsoft login and Graph HTTPS endpoints.
- Only newly received OTP mail is stored, as sender, subject and extracted code; no HTML bodies or attachments are retained/rendered.
- All list, copy, connect and mutation endpoints recheck mailbox grants; the OAuth callback rechecks initiator session and grants.
- Do not claim production collection is live before Microsoft application configuration and real account authorization.

## Review focus

- Authorization races, wrong Microsoft account, replay, logout, revoked grants and configuration changes during callback.
- Cross-mailbox read/copy/manage access, including multiple operators and mailboxes with no shop label.
- Refresh-token rotation, invalid_grant, HTTP429 Retry-After, paging, duplicate receipts and failures without raw provider errors.
- HTML/XSS mail, false OTPs, historical mail, deleted local codes reappearing and stale worker writes.
- First deployment, repeated migration, missing keyring, safe packaging and persistent worker restart after update.
