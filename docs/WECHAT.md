# 可选微信通知

微信能力独立于基本收码功能，不配置也能使用Web后台。

## 配置自己的服务号

部署者需要自己的已认证服务号、可用的消息接口权限和与实际业务场景匹配的模板。模板是否可申请、字段及发送场景以微信平台为准；不要用其他设备事件模板冒充验证码到达事件。

现有代码使用的字段为`thing1`、`character_string15`和`time4`，分别对应设备名称、校验码和时间。模板ID和回调站点由本站管理员自行配置，默认留空、通知默认关闭。字段映射暂为固定的三个字段，没有任意模板自动适配能力。

在后台配置AppID、AppSecret、模板ID和本站HTTPS地址。不要把AppSecret粘贴到Issue、代码或公开配置样例。

在微信平台按实际服务号要求配置：

- 调用微信接口的服务器出口IP白名单。
- 网页授权回调域名，用于扫码绑定后的OAuth回跳。
- 需要的其他接口或域名权限。

网页授权域名和JS接口安全域名是不同的配置。错误10003通常应检查授权请求实际使用的redirect_uri与对应AppID下的网页授权域名，不要只修改JS域名。

## 每个人绑定自己的微信

用户用自己的系统账户登录，打开微信绑定入口生成本人的绑定码，在微信中完成授权并确认。系统按账户权限决定可接收的验证码，不共享管理员的微信身份。

配置更新、解绑、权限变化后，旧的待发送任务可能被取消，防止消息发给不再有权限的人。

## 启动投递worker

先在server目录执行一次诊断：

```bash
/www/server/php/82/bin/php bin/wechat-worker.php --once
```

持续运行：

```bash
/www/server/php/82/bin/php bin/wechat-worker.php --loop
```

正式使用由宝塔进程守护、systemd或已有服务管理器以网站运行用户托管，配置意外退出重启；不要仅在临时SSH窗口里运行。该worker约每3秒检查一次，需自行核对数据库配置、keyring读取权限及出站HTTPS。

代码更新后worker会检查源文件变化并退出，服务管理器应重启它。后台发送测试、观察worker状态及本人微信卡片，才能确认完整链路。

## 提醒方式与限制

消息被微信API受理不代表手机已弹出强提醒。通知声音、折叠到服务号、免打扰、系统通知权限和客户端展示都由微信与手机控制，服务端不能保证等同私人聊天提醒。

项目只将新鲜、授权范围内的验证码用于此通道，不把完整短信正文塞进模板。没有合适模板时应使用Web后台或后续合法通知通道，不用不匹配模板规避平台限制。
