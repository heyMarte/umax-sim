# Umax SIM

自部署的手机卡管理工具，使用 Android 手机采集新收到的验证码短信，通过 Web 后台统一管理号码、设备、余额和人员权限。

> 0.6.0 开源版：PHP 后台＋Android App，MIT 许可证。各部署者连接自己的服务器和手机。

适合电商运营团队、跨境团队及需要集中管理自有手机卡的个人。手机号是主要管理对象，平台和店铺用于区分用途，录入号码不要求先建店铺。

## 能做什么

- **号码管理**：录入手机卡，按国家区号规范号码，关联多个平台和不同名称的店铺，维护余额、充值、套餐到期和保号检查记录。
- **设备接入**：给手机命名、生成接入码、扫码连接自己的后台；不需要手工输入后台设备ID。
- **双卡管理**：查看SIM与手机关联、换卡事件和运行状态；读取不到本机号码时可手动确认，绑定不要求发送验证短信。
- **验证码管理**：新短信上传、验证码提取、按号码或店铺筛选、复制验证码；断网时保留本机待上传队列。
- **多人协作**：独立账户、功能权限与数据范围，按授权分配号码或店铺的可见性。
- **运维**：设备心跳、异常提示、回收站、操作记录、备份与恢复、后台与Android App分别发布。
- **下载分享**：站点`/a`提供下载页面、二维码和短链接。
- **可选微信通知**：使用部署者自己的已认证服务号和匹配的消息模板，按本人绑定与系统授权投递通知。

## 工作方式

Android手机插卡并接收短信 → App通过HTTPS上传到自己的服务器 → Web后台按号码和权限展示 → 可选通知渠道发送验证码提醒。

每个部署者使用自己的服务器、数据库和手机。项目不提供公共接码池、公共短信转发服务或内置第三方收码账户。

## 部署

- 后台：PHP8.2、MySQL8.0或MariaDB10.6+、Nginx、HTTPS。
- App：最低Android6.0/API23。不同厂商的后台保活、权限和安装器行为需分别验证。
- 网站运行目录必须指向`server/public`。
- 无默认管理员账户；安装后通过命令创建。
- 基础功能不需要Composer、Redis或Docker。微信推送需要单独启动投递worker。

建议按以下顺序操作：

1. 阅读[安装说明](docs/INSTALL.md)，部署后台、初始化数据库并创建管理员。
2. 阅读[手机接入说明](docs/ANDROID.md)，安装App、扫码、授权、启动采集。
3. 阅读[备份与更新](docs/OPERATIONS.md)，配置计划任务并掌握覆盖升级。
4. 如需微信通知，阅读[微信配置](docs/WECHAT.md)。

## 当前边界

- 号码规范化目前支持中国、菲律宾；平台预置TikTok、Shopee、Lazada，可通过站点platform_catalog配置追加用途标签，见[平台配置](docs/PLATFORMS.md)。其他国家号码需单独适配验证。
- 店铺是号码用途标记；不接入商品、订单、库存或支付业务。
- 余额为人工查询后的记录，充值记录不会自动计算运营商的实时余额。
- 未取得相应权限、未报告指标或设备在线，均不等于该卡一定能接收验证码。
- 微信通知展示和提醒方式由微信客户端控制，不能保证和私人聊天一样强提醒。
- 在线安装在部分vivo、红米上存在用户反馈的失败。0.5.13在Android6/15模拟器中验证了覆盖安装；厂商真机兼容性仍待确认。浏览器下载APK后覆盖安装可作为备用流程。
- 当前交付APK沿用开发阶段调试签名。正式公开发行应建立固定签名和可持续构建流程；更换签名不能直接覆盖已安装的同包名App。
